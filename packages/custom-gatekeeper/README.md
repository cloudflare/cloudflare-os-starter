# Custom Gatekeeper

This is a credential-free, read-only example for deployment-owned Cloudflare OS integrations. It exposes deployment information through a typed singleton and records every read as an observation.

## Adapt it

Change only the pieces your integration needs:

- `src/types.d.ts`: replace `CustomSession` with the API agents and Gadgets may call.
- `src/types-code.ts`: keep the agent-facing declaration synchronized with `types.d.ts`.
- `src/custom.ts`: replace `getDeploymentInfo()` and its observation description with the real read operation.
- `src/custom.ts`: update vendor, account, resource, and binding metadata.
- `wrangler.jsonc`: add non-secret bindings/variables and a migration when adding Durable Object classes.
- `__tests__/worker.ts`: list every new entrypoint or Durable Object class by name. The test pool reads `ctx.exports` from that file's named exports alone, so one left out is `undefined` there in tests.
- `deployment.jsonc`: provide deployment values and keep the `GATEKEEPER_CUSTOM` service binding generated by `cf-os deploy` (`packages/cf-os/src/core/deployment.ts`).

Put API tokens and OAuth credentials in Wrangler secrets, never `wrangler.jsonc` or `deployment.jsonc`.

## Observer policy

The example's one read reports `subresources: []`, and `CustomGatekeeper.verifyObserverAccess()` allows every observer, because it returns the same low-stakes deployment text to every authenticated user. That is not a safe default for account-specific, tenant-specific, or confidential data.

A real integration must report, on every read, the resources whose access rules govern what it returns, and check each observer against them in `verifyObserverAccess()`. `getHistoricalSubresources()` returns `[]` and `addObserver()`/`removeObserver()` stay no-ops, as upstream's contract for new Gatekeepers asks; a type-check does not catch a missing `getHistoricalSubresources()`. Use upstream's [`write-gatekeeper` skill](https://github.com/cloudflare/cloudflare-os/blob/main/.agents/skills/write-gatekeeper/SKILL.md) for observer design, OAuth, URL-scoped resources, writes and simulation, hooks, and configurator UI.
